# Configuration

Every value below is read from the environment at startup. The defaults suit a developer's machine; a
deployment supplies its own. The ports the service is reached on are not configurable from the environment.

| Variable                | What it sets                                                                                                                                                                                                              | Default                                       | Required          | Secret |
|-------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------|-------------------|--------|
| `OPENAI_API_KEY`        | the credential the AI provider is called with                                                                                                                                                                             | *(none)*                                      | yes               | yes    |
| `OPENAI_BASE_URL`       | where that provider is reached: the base the chat-completions path hangs off, version segment included. One without it makes the provider answer not-found on every call, which reaches the caller as unavailable          | `https://api.openai.com/v1`                   | no                | no     |
| `OPENAI_MODEL`          | which model reads the message. It must be able to call tools; one that cannot answers with text instead, so the turn succeeds having recorded nothing                                                                      | `gpt-4o-mini`                                 | no                | no     |
| `LEDGER_MCP_URL`        | the ledger's base address; the tool path is fixed, and the [ledger's key set](contracts/out/ledger-mcp.md#the-ledgers-key-set) is read under the same address. A wrong one fails every turn as [unavailable](contracts/out/ledger-mcp.md#failures) | `http://localhost:1000`     | yes               | no     |
| `MEMORY_ENABLED`        | whether the service keeps the messages it is handed at all. Off runs it with no database: no message is stored, no purge runs, the caller's token reaches the ledger unread, the change stream is not read, and none of the `when memory is on` variables is read | `true`                              | no                | no     |
| `DB_JDBC_URL`           | the database those messages are kept in                                                                                                                                                                                   | `jdbc:postgresql://localhost:5432/finance_ai` | when memory is on | no     |
| `DB_USER`               | the database account                                                                                                                                                                                                      | *(empty)*                                     | when memory is on | no     |
| `DB_PASSWORD`           | the password for that account                                                                                                                                                                                             | *(empty)*                                     | when memory is on | yes    |
| `LEDGER_TOKEN_ISSUER`   | the issuer a caller token must name — what the ledger mints its caller tokens with. A wrong one refuses every call as unauthenticated, before the provider is reached                                                       | `ledger-service`                              | no                | no     |
| `LEDGER_TOKEN_AUDIENCE` | the audience a caller token must name, on the same terms                                                                                                                                                                  | `mcp-adapter`                                 | no                | no     |
| `LEDGER_JWKS_TIMEOUT`   | how long a fetch of the ledger's key set may take                                                                                                                                                                         | `3s`                                          | no                | no     |
| `MEMORY_MAX_AGE`        | how long a message is kept. Not positive stops startup                                                                                                                                                                    | `365d`                                        | no                | no     |
| `MEMORY_PURGE_INTERVAL` | how often messages past `MEMORY_MAX_AGE` are deleted                                                                                                                                                                      | `1d`                                          | no                | no     |
| `MEMORY_PURGE_BATCH`    | how many messages one purge transaction deletes. Not positive stops startup                                                                                                                                               | `1000`                                        | no                | no     |
| `REDIS_URL`             | where the ledger's change stream is read                                                                                                                                                                                  | `redis://localhost:6379`                      | when memory is on | no     |
| `CDC_STREAM_KEY`        | the stream read, matching the ledger's own                                                                                                                                                                                | `ledger.cdc`                                  | no                | no     |
| `MEMORY_ENTRY_ATTEMPTS` | how many store-answered refusals a change-stream entry gets before it is dropped. Not positive stops startup                                                                                                              | `3`                                           | no                | no     |

A secret belongs in the deployment's secret store, never in a committed file or a log line.
